# _초안 — 아직 기사가 아닌 것들

여기 있는 파일은 **빌드가 쳐다보지 않습니다.** `src/content/` 밖이라
스키마도, 게이트도, 발행 기준도 걸리지 않습니다. 형식 없이 던져 두는 곳입니다.

## 왜 이 폴더가 있나

이 저장소의 기사 한 편에는 frontmatter 필드 스무 개와 게이트 스무 개가 붙습니다.
그건 「틀린 걸 발행하지 않는다」를 위한 장치고, 그 목적에는 잘 맞습니다.

그런데 부작용이 있었습니다 — **자료를 가진 사람이 그걸 넣을 자리가 없다.**
찍어 온 사진, 영수증, 「이거 왜 이래?」 한 줄. 그게 기사가 되려면
누군가 확인하고 형식을 갖춰야 하는데, 그 전 단계를 둘 데가 없었습니다.

여기가 그 자리입니다.

## 어떻게 쓰나

파일 하나 만들어서 아무렇게나 적으면 됩니다. `2026-08-27-올리브영영수증.md` 처럼
날짜와 주제를 파일명에 넣으면 나중에 찾기 쉽습니다.

사진은 같은 폴더에 그냥 넣습니다. 이름은 상관없습니다.

**형식을 지키려고 애쓰지 마십시오.** 형식은 발행할 때 붙입니다.

## 무엇을 적으면 기사가 되나

기억보다 **증거**가 강합니다. 「예전에 얼마였던 것 같은데」는 못 쓰지만,
영수증 사진 한 장은 그대로 숫자가 됩니다.

- **찍은 것** — 영수증, 가격표, 안내문, 메뉴판, 표지판
- **산 것** — 언제, 어디서, 얼마에, 왜 그걸 골랐는지
- **안 하게 된 것** — 예전엔 했는데 지금 안 하는 것과 그 이유
- **막혔던 순간** — 「이거 어떻게 하는 거지」 했던 자리
- **친구에게 설명한 말** — 외국인 친구가 물어봤을 때 뭐라고 답했는지

## 무엇이 되지 않나

- 다른 블로그나 기사에서 가져온 사진 — 이 사이트는 라이선스가 확인된 사진만 씁니다
- 「좋았다」·「예뻤다」 같은 감상만 있는 것 — 나쁘진 않지만 그것만으로는 기사가 안 됩니다
- 남의 얼굴이 알아볼 수 있게 찍힌 사진

## 발행까지

1. 여기 자료가 쌓인다
2. 운영자가 1차 출처로 숫자를 확인한다 (여기가 오래 걸리는 곳입니다)
3. `src/content/` 아래 기사로 옮긴다 — `_글쓰는법.md` 참조
4. `npm.cmd run og` → `npm.cmd run verify` → 커밋

여기 있는 파일은 **지워도 됩니다.** 기사가 된 뒤에는 원본으로만 남습니다.
다만 사진은 지우지 마십시오 — 나중에 「이 사진 어디서 났지」를 겪습니다.
